@lesson 8.1 | Defining functions | 25
@goal Write your own functions with `def`, pass them values, and get results back with `return`.

You've used plenty of functions: `print()`, `len()`, `input()`, `sorted()`. Now you'll make your own. A **function** is a named block of code you can run whenever you like, as often as you like.

```py
def greet(name):
    message = "Namaste, " + name + "!"
    return message

print(greet("Aman"))
print(greet("Riya"))
```

- `def` starts a function **definition**, followed by its name, brackets and a colon.
- `name` is a **parameter**: a variable that receives whatever value the caller passes in. `"Aman"` is the **argument** passed for it.
- The indented block is the function's **body**. Nothing in it runs until the function is **called**.
- `return` sends a value back to wherever the function was called.

Press **Step through** on that example: watch the arrow jump into the function, a new box of local variables appear, and the result come back.

## return is not print

This is the most important idea in this lesson. `print()` shows a value on the screen and the program can't use it again. `return` hands the value back so the caller can store it, test it or calculate with it:

```py
def area(length, width):
    return length * width

room = area(4, 5)
hall = area(10, 6)
print(room + hall)
print(area(2, 3) > 5)
```

A function that has no `return` gives back `None`:

```py
def shout(text):
    print(text.upper())

result = shout("hello")
print(result)
```

## Why bother?

- **Reuse**: write the logic once, call it a hundred times.
- **Names**: `cgl_score(68, 12)` says what it does; the formula alone doesn't.
- **Testing**: you can check a function with different inputs, which is exactly what the **Check** button does with your exercises.

Function names follow the same rules as variables (snake_case). Start them with a verb when you can: `calculate_total`, `is_valid`, `get_grade`.

:::predict
```py
def double(x):
    return x * 2
    print("done")

print(double(double(3)))
```
- 6
+ 12
- 12\ndone
- done\n12
= `return` ends the function immediately, so print("done") never runs. double(3) is 6, and double(6) is 12.
:::

:::recall
Q: What is the difference between a parameter and an argument?
A: A parameter is the variable in the function definition; the argument is the value passed in when you call it.
Q: What is the difference between `return` and `print` in a function?
A: return hands the value back to the caller to use; print only shows it on screen.
Q: What does a function return if it has no return statement?
A: None.
:::

@lesson 8.2 | Parameters and return values | 25
@goal Use default values and keyword arguments, return several values at once, and document a function.

## Default values

A parameter can have a **default**, used when the caller leaves it out:

```py
def cgl_score(correct, wrong, plus=2, minus=0.5):
    return correct * plus - wrong * minus

print(cgl_score(68, 12))
print(cgl_score(68, 12, plus=1, minus=0.25))
```

Parameters with defaults must come after the ones without.

## Keyword arguments

You can name arguments when you call a function. Then their order doesn't matter, and the call explains itself:

```py
def cgl_score(correct, wrong, plus=2, minus=0.5):
    return correct * plus - wrong * minus

print(cgl_score(wrong=12, correct=68))
print(cgl_score(70, 10, minus=1))
```

You already know keyword arguments: `print(..., sep="-")` and `sorted(..., reverse=True)`.

## Returning several values

Return a tuple, and unpack it at the call:

```py
def stats(numbers):
    total = sum(numbers)
    return total, total / len(numbers)

total, average = stats([142, 151, 138, 160])
print(total, average)
```

## Returning early

A function can have several `return`s. The first one reached ends the function. That keeps decisions flat:

```py
def grade(marks):
    if marks >= 90:
        return "A"
    if marks >= 75:
        return "B"
    if marks >= 60:
        return "C"
    return "F"

print(grade(95), grade(80), grade(20))
```

## Docstrings

A string on the first line of the body describes the function. Editors show it, and `help()` prints it:

```py
def cgl_score(correct, wrong):
    """Return the SSC CGL Tier 1 score: +2 per right answer, -0.5 per wrong one."""
    return correct * 2 - wrong * 0.5

print(cgl_score.__doc__)
```

:::predict
```py
def f(a, b=10, c=100):
    return a + b + c

print(f(1), f(1, 2), f(1, c=3))
```
- 111 3 4
+ 111 103 14
- 111 103 104
- 1 3 4
= f(1) uses both defaults: 1 + 10 + 100. f(1, 2) replaces b: 1 + 2 + 100. f(1, c=3) keeps b at 10: 1 + 10 + 3.
:::

:::recall
Q: Where must parameters with default values go?
A: After all the parameters without defaults.
Q: How does a function return two values?
A: `return a, b` returns a tuple; unpack it with `x, y = f()`.
Q: What is a docstring?
A: A string on the first line of a function body that explains what the function does.
:::

@exercise 8.2b | Smallest and largest
Write `min_max(numbers)` that returns a tuple `(smallest, largest)` for a non-empty list, without using `min()` or `max()`.

```starter

    pass
```

```solution
def min_max(numbers):
    smallest = numbers[0]
    largest = numbers[0]
    for n in numbers:
        if n < smallest:
            smallest = n
        if n > largest:
            largest = n
    return smallest, largest

print(min_max([4, 9, 1, 7]))
```


@lesson 8.3 | Scope: where variables live | 20
@goal Know which variables a function can see and change, and write functions that take inputs and return outputs instead of touching globals.

Variables created inside a function are **local**: they exist only while the function runs, and the rest of the program can't see them.

```py error
def make_total():
    total = 42
    return total

make_total()
print(total)
```

Variables created at the top level of the file are **global**. A function can **read** a global:

```py
pass_mark = 40

def passed(marks):
    return marks >= pass_mark

print(passed(55))
```

But as soon as a function **assigns** to a name, Python treats that name as local for the whole function. That causes one of Python's most confusing errors:

```py error
xp = 100

def earn():
    xp = xp + 20
    return xp

earn()
```

`UnboundLocalError` means: you're using a local variable before it was given a value. Python decided `xp` is local (because of the assignment) and then found it read before being set.

## The fix: pass in, return out

Don't reach for globals. Give the function what it needs as **parameters**, and **return** what it produces:

```py
def earn(xp, amount):
    return xp + amount

xp = 100
xp = earn(xp, 20)
print(xp)
```

Functions written this way, which depend only on their inputs and change nothing outside, are called **pure**. They're easy to test and reuse, which is why professionals prefer them. (Python does have a `global` keyword that lets a function change a global variable. You'll rarely need it; reaching for it usually means the design needs rethinking.)

## Lists passed in can be changed

When you pass a list, the function gets the **same list**, not a copy (remember aliasing from Unit 6). Changes inside are visible outside:

```py
def add_bonus(marks):
    for i in range(len(marks)):
        marks[i] += 5

scores = [40, 50]
add_bonus(scores)
print(scores)
```

Sometimes that's what you want. When it isn't, build and return a new list instead.

:::predict
```py
x = 1
def f():
    x = 2
    return x
print(f(), x)
```
- 2 2
+ 2 1
- 1 1
- UnboundLocalError
= The x inside f is a separate local variable. Setting it to 2 doesn't touch the global x, which stays 1.
:::

:::recall
Q: Can code outside a function use a variable created inside it?
A: No. Variables created inside a function are local and disappear when it returns.
Q: What causes UnboundLocalError?
A: A function assigns to a name (making it local) but reads it before giving it a value, often while trying to update a global.
Q: What is a pure function?
A: One that only uses its parameters and returns a result, without changing anything outside itself.
:::

@lesson 8.4 | Functions together, and recursion | 25
@goal Build programs from small functions that call each other, and write simple recursive functions.

## Small functions, big programs

Good programs are built from small functions that each do one job. Then bigger functions combine them:

```py
def is_prime(n):
    if n < 2:
        return False
    for d in range(2, n):
        if n % d == 0:
            return False
    return True

def primes_up_to(limit):
    result = []
    for n in range(2, limit + 1):
        if is_prime(n):
            result.append(n)
    return result

print(primes_up_to(30))
```

`is_prime` is small enough to get right and test on its own. `primes_up_to` reads almost like English because the hard part has a name.

## Recursion: a function that calls itself

Some problems contain smaller copies of themselves. 5! (5 factorial) is 5 times 4!, and 4! is 4 times 3!, and so on down to 0!, which is simply 1. A **recursive** function follows that description directly:

```py
def factorial(n):
    if n == 0:          # base case: answer directly
        return 1
    return n * factorial(n - 1)   # recursive case: a smaller copy

print(factorial(5))
```

Every recursive function needs two parts:

1. a **base case** that answers without calling itself, and
2. a **recursive case** that calls itself on a **smaller** problem, moving towards the base case.

Step through `factorial(3)`: you'll see a stack of `factorial` boxes, each waiting for the one above it to return. Forget the base case and the stack grows until Python gives up:

```py error
def forever(n):
    return forever(n + 1)

forever(1)
```

:::tip
Loops can do everything recursion does, and in Python they're usually faster. Recursion shines on problems with a nested shape, such as folders inside folders and trees, and it's a favourite in coding interviews. You'll use it again in the interview track.
:::

:::predict
```py
def count(n):
    if n == 0:
        return "go"
    return str(n) + " " + count(n - 1)

print(count(3))
```
- go
- 3 2 1
+ 3 2 1 go
- go 1 2 3
= count(3) is "3 " + count(2), which is "2 " + count(1), which is "1 " + count(0), and count(0) is "go".
:::

:::recall
Q: What two parts does every recursive function need?
A: A base case that returns without recursing, and a recursive case that calls itself on a smaller problem.
Q: What happens if a recursive function has no base case?
A: It calls itself forever until Python stops it with a RecursionError.
Q: Why split a program into small functions?
A: Each one is easier to understand, test and reuse, and the big function reads clearly because the pieces have names.
:::

You'll build four functions that turn a dictionary of marks into a report card. Each subject is out of 50.

:::recall
Q: Why should `report` return a string instead of printing it?
A: A returned string can be printed, saved to a file, emailed or tested. Printing only shows it once.

A: Collect them in a list and use `"\n".join(lines)`.

@exercise 8.5a | Build the toolkit | project
Write `total`, `percentage`, `grade` and `report` as described in the lesson. `report` must **return** the text (the starter prints it for you).

```starter
def total(marks):
    pass

def percentage(obtained, maximum):
    pass

def grade(pct):
    pass

def report(name, marks, out_of=50):
    pass

print(report("Aman", {"Reasoning": 45, "English": 41, "Maths": 38, "GK": 33}))
```

```solution
def total(marks):
    result = 0
    for mark in marks.values():
        result += mark
    return result

def percentage(obtained, maximum):
    return round(obtained / maximum * 100, 1)

def grade(pct):
    if pct >= 90:
        return "A"
    if pct >= 75:
        return "B"
    if pct >= 60:
        return "C"
    if pct >= 40:
        return "D"
    return "F"

def report(name, marks, out_of=50):
    lines = [f"Report card: {name}"]
    for subject, mark in marks.items():
        lines.append(f"{subject:<12}{mark}/{out_of}")
    got = total(marks)
    maximum = out_of * len(marks)
    pct = percentage(got, maximum)
    lines.append(f"Total: {got}/{maximum} ({pct}%) Grade: {grade(pct)}")
    return "\n".join(lines)

print(report("Aman", {"Reasoning": 45, "English": 41, "Maths": 38, "GK": 33}))
```

```test

    need(name, "function")

expect("total({})", 0)

expect("percentage(1, 3)", 33.3)
for p, g in [(95, "A"), (90, "A"), (89.9, "B"), (75, "B"), (60, "C"), (40, "D"), (39.9, "F")]:
    expect(f"grade({p})", g)
expect('report("Aman", {"Reasoning": 45, "English": 41, "Maths": 38, "GK": 33})', "Report card: Aman\nReasoning   45/50\nEnglish     41/50\nMaths       38/50\nGK          33/50\nTotal: 157/200 (78.5%) Grade: B")
```
