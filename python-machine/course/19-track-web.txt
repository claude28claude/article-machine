@lesson D.1 | How the web works | 25
@goal Describe what happens in an HTTP request and response, and take URLs and JSON apart in Python.

Every time you open a page, your browser (the **client**) sends a **request** to a **server**, which sends back a **response**. A web app is just a program that turns requests into responses.

## The URL

```text
https://api.example.in/articles/21?lang=en&format=json
scheme  host           path        query
```

```py
from urllib.parse import urlparse, parse_qs

url = "https://api.example.in/articles/21?lang=en&format=json"
parts = urlparse(url)
print(parts.scheme, parts.netloc, parts.path)
print(parse_qs(parts.query))
```

## The request

A request has a **method** (what to do), a **path** (to what), **headers** (extra information) and sometimes a **body** (data sent along).

| Method | Meaning | Example |
| --- | --- | --- |
| GET | read something | open article 21 |
| POST | create something | submit a quiz answer |
| PUT / PATCH | change something | update your profile |
| DELETE | remove something | delete a note |

## The response

A response has a **status code**, headers and a body: HTML for pages, **JSON** for APIs.

| Code | Meaning |
| --- | --- |
| 200 | OK |
| 201 | Created |
| 301 / 302 | Moved (redirect) |
| 400 | Bad request (your fault: invalid input) |
| 401 / 403 | Not logged in / not allowed |
| 404 | Not found |
| 500 | Server error (the server's fault) |

Modelling one in plain Python makes the idea concrete:

```py
import json

request = {"method": "GET", "path": "/articles/21", "headers": {"Accept": "application/json"}}
response = {
    "status": 200,
    "headers": {"Content-Type": "application/json"},
    "body": json.dumps({"number": 21, "heading": "Protection of life and personal liberty"}),
}
print(request["method"], request["path"], "->", response["status"])
print(json.loads(response["body"])["heading"])
```

That's all a web framework does at heart: receive the first dictionary, produce the second.

:::recall
Q: What are the four parts of a URL like https://site.in/path?x=1?
A: Scheme (https), host (site.in), path (/path) and query (x=1).
Q: What do the HTTP methods GET and POST mean?
A: GET reads something; POST sends data to create something.
Q: What is the difference between 4xx and 5xx status codes?
A: 4xx means the client made a mistake (like 404 not found); 5xx means the server failed.
:::

```solution
from urllib.parse import urlparse, parse_qs

def parse_url(url):
    p = urlparse(url)
    query = {k: v[0] for k, v in parse_qs(p.query).items()}
    return {"scheme": p.scheme, "host": p.netloc, "path": p.path, "query": query}
```

@lesson D.2 | Build a tiny web framework | 30
@goal See how frameworks like Flask route requests by building a small one with a decorator.

Flask code looks like this:

```py norun
@app.get("/articles/<n>")
def article(n):
    return {"number": n}
```

Magic? No: you already know every piece. `@app.get(...)` is a **decorator** (Unit 14) that stores your function in a dictionary of routes. When a request arrives, the framework looks up its path and calls the stored function. Let's build that.

## Registering routes with a decorator

```py
ROUTES = {}

def route(path):
    def register(func):
        ROUTES[path] = func
        return func
    return register


@route("/")
def home():
    return "Welcome to the Article API"


@route("/about")
def about():
    return "Built in Python"


def handle(path):
    func = ROUTES.get(path)
    if func is None:
        return 404, "Not found"
    return 200, func()


print(handle("/"))
print(handle("/about"))
print(handle("/missing"))
```

`route(path)` returns the real decorator, which records the function and gives it back unchanged.

## Paths with parameters

Real apps need paths like `/articles/21`. A pattern `/articles/<n>` matches when both have the same number of parts and every fixed part is equal; the `<...>` parts become arguments:

```py
def match(pattern, path):
    p_parts = pattern.strip("/").split("/")
    parts = path.strip("/").split("/")
    if len(p_parts) != len(parts):
        return None
    params = {}
    for p, actual in zip(p_parts, parts):
        if p.startswith("<") and p.endswith(">"):
            params[p[1:-1]] = actual
        elif p != actual:
            return None
    return params

print(match("/articles/<n>", "/articles/21"))
print(match("/articles/<n>", "/parts/III"))
```

The handler then gets those values as keyword arguments: `func(**params)`.

:::recall
Q: What does a decorator like `@app.get("/")` do in a web framework?
A: Registers the function in the framework's table of routes so requests to that path call it.
Q: How can `/articles/<n>` match `/articles/21`?
A: Split both into parts; equal counts, fixed parts identical, and each `<name>` part captures the real value as a parameter.
:::

```starter
def match(pattern, path):
```
```solution
    p_parts = pattern.strip("/").split("/")
    parts = path.strip("/").split("/")
    if len(p_parts) != len(parts):
```

@lesson D.3 | Databases with SQL | 30

Files and JSON work for small data. Real apps use a **database**, and most databases speak **SQL**. Python includes **SQLite**: a complete SQL database stored in a single file (or in memory), used inside every phone and browser.

```file articles.json
  {"number": 112, "heading": "Annual financial statement", "part": "V"},
  {"number": 280, "heading": "Finance Commission", "part": "XII"},

  {"number": 352, "heading": "Proclamation of Emergency", "part": "XVIII"},
  {"number": 360, "heading": "Provisions as to financial emergency", "part": "XVIII"}
]
```

## Create, insert, query

```py
import json
import sqlite3

conn = sqlite3.connect(":memory:")          # or "articles.db" for a file
conn.execute("CREATE TABLE articles (number INTEGER PRIMARY KEY, heading TEXT, part TEXT)")

with open("articles.json", encoding="utf-8") as f:
    rows = [(a["number"], a["heading"], a["part"]) for a in json.load(f)]
conn.executemany("INSERT INTO articles VALUES (?, ?, ?)", rows)
conn.commit()

for number, heading in conn.execute("SELECT number, heading FROM articles WHERE part = ? ORDER BY number", ("III",)):
    print(number, heading)
```

| SQL | Meaning |
| --- | --- |
| `CREATE TABLE t (col TYPE, ...)` | make a table |
| `INSERT INTO t VALUES (?, ?)` | add a row |
| `SELECT cols FROM t WHERE cond ORDER BY col LIMIT n` | read rows |
| `UPDATE t SET col = ? WHERE cond` | change rows |
| `DELETE FROM t WHERE cond` | remove rows |
| `SELECT part, COUNT(*) FROM t GROUP BY part` | count per group |

## Never build SQL from user input

The `?` placeholders matter more than anything else on this page. Gluing user text into SQL with f-strings lets an attacker rewrite your query (**SQL injection**, one of the most common real-world security holes):

```py norun
# DANGEROUS: never do this
conn.execute(f"SELECT * FROM articles WHERE heading LIKE '%{user_text}%'")

# SAFE: the database treats the value purely as data
conn.execute("SELECT * FROM articles WHERE heading LIKE ?", (f"%{user_text}%",))
```

## Grouping and counting

```py
import json
import sqlite3

conn = sqlite3.connect(":memory:")
conn.execute("CREATE TABLE articles (number INTEGER PRIMARY KEY, heading TEXT, part TEXT)")
with open("articles.json", encoding="utf-8") as f:
    conn.executemany("INSERT INTO articles VALUES (:number, :heading, :part)", json.load(f))

query = "SELECT part, COUNT(*) FROM articles GROUP BY part ORDER BY COUNT(*) DESC, part"
print(conn.execute(query).fetchall())
```

`:number` style placeholders take values from dictionaries, which fits JSON data neatly.

:::recall
Q: What do the `?` placeholders in SQL protect against?
A: SQL injection: values are passed as data and can never change the query itself.
Q: Which SQL clause counts rows per group?
A: `GROUP BY`, as in `SELECT part, COUNT(*) FROM articles GROUP BY part`.
Q: What does `conn.commit()` do?
A: Saves the changes made since the last commit to the database.
:::

@lesson D.4 | Flask and FastAPI on your laptop | 30

Now the real thing. On your laptop, in a virtual environment, install a framework. **Flask** is simple and famous; **FastAPI** is modern and uses type hints to validate input and write documentation for you.

## Flask

`pip install flask`, then save as `app.py`:

```py norun
from flask import Flask, jsonify

app = Flask(__name__)

ARTICLES = {14: "Equality before law", 21: "Protection of life and personal liberty"}


@app.get("/articles/<int:n>")
def article(n):
    if n not in ARTICLES:
        return jsonify({"error": "Article not found"}), 404
    return jsonify({"number": n, "heading": ARTICLES[n]})


if __name__ == "__main__":
    app.run(debug=True)
```

Run `python app.py` and open `http://127.0.0.1:5000/articles/21`. Compare it with your tiny framework: a decorator registers the route, `<int:n>` captures and converts the parameter, and the function returns a body and a status.

```solution
import json
import sqlite3

def load(path):
    conn = sqlite3.connect(":memory:")
    conn.execute("CREATE TABLE articles (number INTEGER PRIMARY KEY, heading TEXT, part TEXT)")
    with open(path, encoding="utf-8") as f:
        conn.executemany("INSERT INTO articles VALUES (:number, :heading, :part)", json.load(f))
    return conn

def get_article(conn, n):
    row = conn.execute("SELECT number, heading, part FROM articles WHERE number = ?", (n,)).fetchone()
    if row is None:
        return None
    return {"number": row[0], "heading": row[1], "part": row[2]}

def list_part(conn, part):
    numbers = [n for (n,) in conn.execute("SELECT number FROM articles WHERE part = ? ORDER BY number", (part,))]
    return {"part": part, "count": len(numbers), "articles": numbers}
```

```solution
import json
import sqlite3

def load(path):
    conn = sqlite3.connect(":memory:")
    conn.execute("CREATE TABLE articles (number INTEGER PRIMARY KEY, heading TEXT, part TEXT)")
    with open(path, encoding="utf-8") as f:
        conn.executemany("INSERT INTO articles VALUES (:number, :heading, :part)", json.load(f))
    return conn

def match(pattern, path):
    p_parts = pattern.strip("/").split("/")
    parts = path.strip("/").split("/")
    if len(p_parts) != len(parts):
        return None
    params = {}
    for p, actual in zip(p_parts, parts):
        if p.startswith("<") and p.endswith(">"):
            params[p[1:-1]] = actual
        elif p != actual:
            return None
    return params

def reply(status, data):
    return status, json.dumps(data)

def handle(conn, method, path, query):
    article = match("/articles/<n>", path)
    part = match("/parts/<part>", path)
    search = match("/search", path)
    if article is None and part is None and search is None:
        return reply(404, {"error": "Not found"})
    if method != "GET":
        return reply(405, {"error": "Method not allowed"})
    if article is not None:
        n = article["n"]
        row = None
        if n.isdigit():
            row = conn.execute("SELECT number, heading, part FROM articles WHERE number = ?", (int(n),)).fetchone()
        if row is None:
            return reply(404, {"error": "Article not found"})
        return reply(200, {"number": row[0], "heading": row[1], "part": row[2]})
    if part is not None:
        numbers = [x for (x,) in conn.execute("SELECT number FROM articles WHERE part = ? ORDER BY number", (part["part"],))]
        return reply(200, {"part": part["part"], "count": len(numbers), "articles": numbers})
    q = (query or {}).get("q", "").strip()
    if len(q) < 3:
        return reply(400, {"error": "Search needs at least 3 characters"})
    rows = conn.execute("SELECT number, heading FROM articles WHERE heading LIKE ? ORDER BY number", (f"%{q}%",))
    return reply(200, {"results": [{"number": num, "heading": h} for num, h in rows]})
```
