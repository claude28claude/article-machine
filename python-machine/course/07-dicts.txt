@lesson 7.1 | Tuples and unpacking | 20
@goal Group fixed values in tuples and unpack them into separate variables in one line.

A **tuple** is like a list that can't be changed. You write it with round brackets:

```py
point = (3, 4)
exam = ("SSC CGL", 2026, "Tier 1")
print(exam[0], exam[1])
print(len(exam))
```

Indexing, slicing, `len()` and `in` work just as with lists. What you can't do is change it:

```py error
exam = ("SSC CGL", 2026, "Tier 1")
exam[1] = 2027
```

Why have a list that can't change? For values that belong together and **shouldn't** change: a date, a coordinate, a (name, score) pair. If code elsewhere tries to change it by mistake, Python stops it.

## Unpacking

You can split a tuple (or a list) into separate variables in one line. The number of names must match the number of items:

```py
exam = ("SSC CGL", 2026, "Tier 1")
name, year, tier = exam
print(name)
print(year)
```

This gives Python's famous one-line swap. The right side builds a tuple `(b, a)` first, then unpacks it:

```py
a = "Physics"
b = "Maths"
a, b = b, a
print(a, b)
```

Compare that with the three lines and the `temp` variable you needed in Unit 2.

## Tuples in loops

Lists of tuples are everywhere in real code, and a `for` loop can unpack each one:

```py
scores = [("Polity", 42), ("History", 38), ("Economy", 45)]
for subject, mark in scores:
    print(f"{subject}: {mark}")
```

That's exactly what `enumerate()` was doing in Unit 6: giving you `(number, item)` tuples.

:::predict
```py
x, y, z = "SSC"
print(z, y, x)
```
- SSC
+ C S S
- S S C
- Error
= A string is a sequence too, so its three characters unpack into x, y and z. Printing them backwards gives C S S.
:::

:::recall
Q: What is the main difference between a tuple and a list?
A: A tuple can't be changed after it's made (immutable); a list can.
Q: How do you swap two variables in one line?
A: `a, b = b, a`.
Q: What does `for subject, mark in pairs:` do?
A: Loops over a list of pairs and unpacks each pair into the two names.
:::

@lesson 7.2 | Dictionaries | 25
@goal Store and look up values by key, and loop over keys and values together.

A list finds things by **position**. A **dictionary** finds things by **key**, like a real dictionary finds a meaning by its word. You write it with braces, as `key: value` pairs:

```py
articles = {
    14: "Equality before law",
    21: "Protection of life and personal liberty",
    32: "Remedies for enforcement of rights conferred by this Part",
}
print(articles[21])
print(len(articles))
```

These are the official headings from the Constitution of India, the same ones in your Article Machine. Looking up article 21 doesn't search through the others: dictionaries jump straight to the key, which keeps them fast even with millions of entries.

## Adding, changing, removing

```py
marks = {"Polity": 42, "History": 38}
marks["Economy"] = 45      # add a new key
marks["History"] = 40      # change an existing one
del marks["Polity"]        # remove a key
print(marks)
print("Economy" in marks)
```

`in` checks **keys**, not values.

## Missing keys

Asking for a key that isn't there raises a `KeyError`:

```py error
marks = {"Polity": 42}
print(marks["Biology"])
```

Use `get()` when a key might be missing. It returns `None`, or a default you choose:

```py
marks = {"Polity": 42}
print(marks.get("Biology"))
print(marks.get("Biology", 0))
```

## Looping

```py
capitals = {"Rajasthan": "Jaipur", "Kerala": "Thiruvananthapuram", "Assam": "Dispur"}
for state in capitals:
    print(state)
for state, city in capitals.items():
    print(f"{city} is the capital of {state}")
print(list(capitals.keys()))
print(list(capitals.values()))
```

- Looping over a dictionary gives its **keys**.
- `.items()` gives `(key, value)` pairs, which unpack nicely.
- Dictionaries remember the order you added things in.

Keys must be unchangeable values: strings, numbers or tuples. Values can be anything, even lists or other dictionaries.

:::predict
```py
d = {"a": 1, "b": 2}
d["a"] = d["b"] + 10
d["c"] = d.get("z", 5)
print(d)
```
- {'a': 1, 'b': 2, 'c': 5}
+ {'a': 12, 'b': 2, 'c': 5}
- {'a': 12, 'b': 2, 'c': None}
- KeyError
= d["a"] becomes 2 + 10. "z" isn't a key, so get returns the default 5, which is stored under "c".
:::

:::recall
Q: How do you read the value for a key, without crashing if the key is missing?
A: `d.get(key)` returns None if it's missing; `d.get(key, default)` returns your default.
Q: What does `for k, v in d.items():` loop over?
A: Every key and value pair in the dictionary.
Q: What does `key in d` check?
A: Whether the key exists in the dictionary. It does not look at the values.
:::

@lesson 7.3 | Counting and grouping | 25
@goal Use dictionaries to count things, find the most common one, and group items together.

## The counting pattern

This pattern appears in nearly every data task: counting votes, words, errors, sales.

```py
votes = ["Riya", "Dev", "Riya", "Sana", "Riya", "Dev"]
counts = {}
for name in votes:
    counts[name] = counts.get(name, 0) + 1
print(counts)
```

Read the key line carefully: get the current count (0 if this name is new), add 1, store it back.

## Finding the most common

Loop over the items and keep the best so far, the same pattern as finding a maximum:

```py
counts = {"Riya": 3, "Dev": 2, "Sana": 1}
winner = None
best = 0
for name, n in counts.items():
    if n > best:
        winner, best = name, n
print(winner, best)
```

## Grouping into lists

A dictionary's values can be lists, which lets you **group** items:

```py
cities = ["Agra", "Bhopal", "Ajmer", "Bikaner", "Chennai"]
groups = {}
for city in cities:
    letter = city[0]
    if letter not in groups:
        groups[letter] = []
    groups[letter].append(city)
print(groups)
```

## Joining a list into text

To print a list neatly, `join` glues its strings together with a separator you choose:

```py
cities = ["Agra", "Ajmer"]
print(", ".join(cities))
print(" > ".join(["Unit 7", "Lesson 3", "Exercise b"]))
```

`join` only works on strings: convert numbers first with `str()`.

## Records: dictionaries inside dictionaries

```py
student = {
    "name": "Aman",
    "exam": "SSC CGL",
    "marks": {"Reasoning": 45, "English": 41, "Maths": 38, "GK": 33},
}
print(student["marks"]["English"])
total = 0
for subject, mark in student["marks"].items():
    total += mark
print(student["name"], "total:", total)
```

This shape (named fields, some of them nested) is exactly what JSON data looks like, which you'll load from files in Unit 12.

:::predict
```py
counts = {}
for ch in "banana":
    counts[ch] = counts.get(ch, 0) + 1
print(counts)
```
- {'b': 1, 'a': 1, 'n': 1}
+ {'b': 1, 'a': 3, 'n': 2}
- {'a': 3, 'n': 2, 'b': 1}
- {'banana': 1}
= Each letter's count goes up every time it appears. Keys keep the order they were first added: b, a, n.
:::

:::recall
Q: Write the counting pattern for a list called items.
A: `counts = {}` then `for x in items: counts[x] = counts.get(x, 0) + 1`.
Q: How do you print the list ["a", "b"] as `a, b`?
A: `", ".join(["a", "b"])`. All items must be strings.
Q: How would you read Aman's English marks from `student = {"marks": {"English": 41}}`?
A: Chain the keys: `student["marks"]["English"]`.
:::

@lesson 7.4 | Sets | 20
@goal Keep only unique items, test membership quickly, and compare groups with set operations.

A **set** is an unordered collection with **no duplicates**. You write it with braces, but without `key:` parts:

```py
subjects = {"Polity", "History", "Polity", "Economy", "History"}
print(len(subjects))
print("Economy" in subjects)
```

The duplicates vanish. Sets don't keep any order, so the order Python prints them in may differ from how you typed them. When you need a stable order, use `sorted()`, which returns a list.

## Removing duplicates

Turning a list into a set is the quickest way to drop duplicates:

```py
attempts = ["Maths", "GK", "Maths", "English", "GK", "Maths"]
unique = sorted(set(attempts))
print(unique)
```

`set()` with nothing inside makes an empty set. (`{}` makes an empty dictionary, not a set.)

```py
seen = set()
seen.add("Polity")
seen.add("Polity")
seen.discard("Biology")   # no error if missing; remove() would raise one
print(seen)
```

## Set maths

Sets answer questions like "what do these two groups have in common?" in one step:

```py
aman = {"Polity", "History", "Economy", "Maths"}
riya = {"Maths", "English", "Polity", "Science"}
print(sorted(aman & riya))   # in both (intersection)
print(sorted(aman | riya))   # in either (union)
print(sorted(aman - riya))   # in aman but not riya (difference)
```

| Operator | Method | Meaning |
| --- | --- | --- |
| `a & b` | `a.intersection(b)` | items in both |
| `a \| b` | `a.union(b)` | items in either |
| `a - b` | `a.difference(b)` | items in a, not in b |
| `a ^ b` | `a.symmetric_difference(b)` | items in exactly one |

Checking `x in some_set` is very fast, even for huge sets. Lists have to check items one by one. That speed matters a lot in the interview track.

:::predict
```py
a = {1, 2, 3, 4}
b = {3, 4, 5}
print(sorted(a - b), sorted(a & b))
```
+ [1, 2] [3, 4]
- [5] [3, 4]
- [1, 2, 5] [3, 4]
- [1, 2] [1, 2, 3, 4, 5]
= a - b keeps what is only in a (1 and 2). a & b keeps what is in both (3 and 4).
:::

:::recall
Q: What happens to duplicates in a set?
A: A set keeps only one copy of each item, so duplicates disappear.
Q: How do you make an empty set?
A: `set()`. Empty braces `{}` make an empty dictionary.
Q: What do `a & b`, `a | b` and `a - b` give for sets?
A: Items in both; items in either; items in a but not in b.
:::
