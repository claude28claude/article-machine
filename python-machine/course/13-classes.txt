@lesson 13.1 | Classes and objects | 25
@goal Define a class, create objects from it, and give them attributes and methods.

So far data and the functions that use it have lived apart: a dictionary of marks here, an `average()` function there. A **class** bundles them together. It's a blueprint; each **object** (or **instance**) made from it has its own data and knows how to work with it.

You've used objects all along: every string is an object of class `str`, and `"hi".upper()` calls a method that belongs to it. Now you'll write your own classes.

```py
class MockTest:
    def __init__(self, name, correct, wrong):
        self.name = name
        self.correct = correct
        self.wrong = wrong

    def score(self):
        return self.correct * 2 - self.wrong * 0.5


t1 = MockTest("Mock 1", 68, 12)
t2 = MockTest("Mock 2", 75, 10)
print(t1.name, t1.score())
print(t2.name, t2.score())
```

## The pieces

- `class MockTest:` starts the blueprint. Class names use **CapitalizedWords**.
- `__init__` is the **initialiser**: Python runs it automatically when you create an object, to set up its starting data. (Those double underscores are pronounced "dunder".)
- `self` is the object being set up or used. `self.correct = correct` stores a value **on the object**: an **attribute**.
- `score(self)` is a **method**: a function that belongs to the class and works on `self`.
- `MockTest("Mock 1", 68, 12)` creates an object. Python passes the new object as `self` for you; you supply the other arguments.

Step through the example: you'll see two separate objects, each with its own `correct` and `wrong`.

## Objects keep their own data

```py
class MockTest:
    def __init__(self, name, correct, wrong):
        self.name = name
        self.correct = correct
        self.wrong = wrong

    def attempted(self):
        return self.correct + self.wrong

    def accuracy(self):
        return round(self.correct / self.attempted() * 100, 1)


test = MockTest("Mock 3", 72, 18)
print(test.attempted(), test.accuracy())
test.wrong = 8          # attributes can be changed
print(test.attempted(), test.accuracy())
```

Methods can call other methods through `self`, as `accuracy` calls `self.attempted()`.


:::

:::recall

A: A class is a blueprint; an object is one thing made from it, with its own data.

```starter
class Rectangle:
```

```solution
        self.width = width
        self.height = height
```

@lesson 13.2 | State, printing and class attributes | 25
@goal Write methods that change an object, make objects print nicely with `__str__` and `__repr__`, and share data between all objects with class attributes.

## Methods that change the object

Objects shine when they **remember** things between method calls:

```py
class Wallet:
    def __init__(self, owner, balance=0):
        self.owner = owner
        self.balance = balance

    def add(self, amount):
        self.balance += amount

    def spend(self, amount):
        if amount > self.balance:
            raise ValueError("not enough money")
        self.balance -= amount


w = Wallet("Aman", 500)
w.add(250)
w.spend(120)
print(w.balance)
```

The object protects its own rules: `spend` refuses to go below zero. Code outside doesn't need to remember that rule; the class enforces it everywhere.

## Printing objects: __str__ and __repr__

By default, printing an object shows something unhelpful like `<__main__.Wallet object at 0x...>`. Two special methods fix that:

- `__str__` returns the friendly text `print()` and `str()` use.
- `__repr__` returns an unambiguous, developer-facing text, ideally looking like the code that creates the object. You see it in lists, in the console and in debuggers.

```py
class Book:
    def __init__(self, title, author):
        self.title = title
        self.author = author

    def __str__(self):
        return f"{self.title} by {self.author}"

    def __repr__(self):
        return f"Book({self.title!r}, {self.author!r})"


b = Book("Godan", "Munshi Premchand")
print(b)
print([b])
```

`!r` inside an f-string uses `repr()`, which adds the quotes.


```starter
class Wallet:
    def __init__(self, owner, balance=0):
        self.owner = owner
        self.balance = balance
```

@lesson 13.3 | Inheritance | 25
@goal Build specialised classes from general ones with inheritance, `super()` and overriding.

Often several classes share most of their behaviour. **Inheritance** lets a new class start from an existing one and change only what's different.

```py
class Exam:
    def __init__(self, name, questions, marks_each):
        self.name = name
        self.questions = questions
        self.marks_each = marks_each

    def max_marks(self):
        return self.questions * self.marks_each

    def score(self, correct, wrong):
        return correct * self.marks_each


class NegativeMarkingExam(Exam):
    def __init__(self, name, questions, marks_each, penalty):
        super().__init__(name, questions, marks_each)
        self.penalty = penalty

    def score(self, correct, wrong):
        return correct * self.marks_each - wrong * self.penalty


school = Exam("School test", 50, 1)
cgl = NegativeMarkingExam("SSC CGL Tier 1", 100, 2, 0.5)
print(school.max_marks(), school.score(40, 10))
print(cgl.max_marks(), cgl.score(68, 12))
```

- `class NegativeMarkingExam(Exam):` means "a NegativeMarkingExam **is an** Exam". It **inherits** everything: `max_marks` works without being rewritten.
- `super().__init__(...)` runs the parent's `__init__`, so the shared setup isn't duplicated.
- Defining `score` again **overrides** the parent's version for this class only.

## Polymorphism

Code can treat different classes the same way, as long as they share the method names. Each object runs its own version:

```py
class Exam:
    def __init__(self, name):
        self.name = name
    def score(self, correct, wrong):
        return correct

class NegativeMarkingExam(Exam):
    def score(self, correct, wrong):
        return correct * 2 - wrong * 0.5

for exam in [Exam("Class test"), NegativeMarkingExam("Mock")]:
    print(exam.name, exam.score(10, 4))
```

`isinstance(obj, Class)` checks the family: a `NegativeMarkingExam` object is also an instance of `Exam`.

:::tip
Use inheritance for a true "is a" relationship. If a class merely **uses** another (a Library **has** Books), store the object as an attribute instead. That's called composition, and it's usually the simpler choice.
:::

:::predict
```py
class A:
    def hello(self):
        return "A"
    def greet(self):
        return "I am " + self.hello()

class B(A):
    def hello(self):
        return "B"

print(B().greet(), isinstance(B(), A))
```
- I am A True
+ I am B True
- I am B False
- Error
= greet is inherited from A, but self is a B object, so self.hello() runs B's version. A B is also an A.
:::

:::recall
Q: What does `class Child(Parent):` mean?
A: Child inherits all of Parent's attributes and methods, and can add or override them.
Q: What does `super().__init__(...)` do?
A: Runs the parent class's `__init__` so the shared setup isn't duplicated.
Q: What is overriding?
A: Defining a method in the child class with the same name as one in the parent, replacing it for the child.
:::

```starter
import math

class Shape:
```

@lesson 13.4 | Special methods and properties | 25
@goal Make your objects work with `+`, `==`, `<`, `len()` and `in`, and use `@property` for computed and protected attributes.

Python's operators call special **dunder methods** behind the scenes. `a + b` calls `a.__add__(b)`; `len(x)` calls `x.__len__()`. Define them, and your objects work with Python's syntax.

```py
class Money:
    def __init__(self, rupees):
        self.rupees = rupees

    def __add__(self, other):
        return Money(self.rupees + other.rupees)

    def __eq__(self, other):
        return self.rupees == other.rupees

    def __lt__(self, other):
        return self.rupees < other.rupees

    def __repr__(self):
        return f"Money({self.rupees})"


fees = Money(100) + Money(250)
print(fees)
print(fees == Money(350))
print(sorted([Money(50), Money(10), Money(30)]))
```

`__lt__` (less than) is all `sorted()` needs to sort your objects.

| Method | Called by |
| --- | --- |
| `__add__` | `a + b` |
| `__eq__` | `a == b` |
| `__lt__` | `a < b`, `sorted()` |
| `__len__` | `len(a)` |
| `__contains__` | `x in a` |
| `__str__` / `__repr__` | `print(a)` / the console |

```py
class Syllabus:
    def __init__(self, topics):
        self.topics = list(topics)

    def __len__(self):
        return len(self.topics)

    def __contains__(self, topic):
        return topic.lower() in [t.lower() for t in self.topics]


s = Syllabus(["Polity", "History", "Economy"])
print(len(s), "polity" in s, "Biology" in s)
```

## @property: attributes that are calculated

Sometimes a value should be **worked out** from other data, but read like a normal attribute. `@property` does that:

```py
class Student:
    def __init__(self, name, marks):
        self.name = name
        self.marks = marks

    @property
    def average(self):
        return round(sum(self.marks) / len(self.marks), 1)


s = Student("Aman", [72, 81, 90])
print(s.average)        # no brackets
s.marks.append(60)
print(s.average)        # always up to date
```

A property can also **guard** an attribute with a setter that checks new values:

```py
class Candidate:
    def __init__(self, age):
        self.age = age          # goes through the setter below

    @property
    def age(self):
        return self._age

    @age.setter
    def age(self, value):
        if not 18 <= value <= 60:
            raise ValueError("age must be 18 to 60")
        self._age = value


c = Candidate(25)
c.age = 30
print(c.age)
try:
    c.age = 12
except ValueError as e:
    print("Refused:", e)
```

The underscore in `_age` is a convention meaning "internal: use `age` instead".

:::predict
```py
class Team:
    def __init__(self, *names):
        self.names = names
    def __len__(self):
        return len(self.names)
    def __contains__(self, name):
        return name in self.names

```
- 1 True False

:::recall
Q: Which method makes `a + b` work for your objects?
A: `__add__(self, other)`.
Q: What does `sorted()` need from your class to sort its objects?
A: A `__lt__` method (less than).
Q: What does `@property` do?
A: Lets a method be read like an attribute (no brackets), useful for calculated values or for guarding an attribute with a setter.

@exercise 13.4a | A Vector
Write `Vector(x, y)` with:

- `__add__`: `Vector(1, 2) + Vector(3, 4)` is `Vector(4, 6)`

- `__repr__`: `Vector(4, 6)`
- `length()`: the distance from the origin, `(x**2 + y**2) ** 0.5`

```starter
class Vector:
    def __init__(self, x, y):
        self.x = x
        self.y = y
```

```solution
class Vector:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __add__(self, other):
        return Vector(self.x + other.x, self.y + other.y)

    def __eq__(self, other):
        return self.x == other.x and self.y == other.y

    def __repr__(self):
        return f"Vector({self.x}, {self.y})"

    def length(self):
        return (self.x ** 2 + self.y ** 2) ** 0.5
```

```test

expect("Vector(1, 2) == Vector(2, 1)", False)
expect("repr(Vector(1, 2) + Vector(3, 4))", "Vector(4, 6)")
expect("Vector(3, 4).length()", 5.0)
```

:::hints
- `__add__` returns a new Vector built from the sums.
- `__eq__` returns True when both coordinates match.
- `__repr__` returns an f-string like `f"Vector({self.x}, {self.y})"`.
:::

@exercise 13.4b | Average as a property
Write `Student(name, marks)` where `marks` is a list, with:

- a property `average` (rounded to 1 place, `0` for an empty list)
- a property `grade`: `A` if average >= 90, `B` if >= 75, `C` if >= 60, else `F`

Both must update automatically when marks change.

```starter

    def __init__(self, name, marks):
        self.name = name
        self.marks = marks
```

```solution
class Student:
    def __init__(self, name, marks):
        self.name = name
        self.marks = marks

    @property
    def average(self):
        if not self.marks:
            return 0
        return round(sum(self.marks) / len(self.marks), 1)

    @property
    def grade(self):
        avg = self.average
        if avg >= 90:
            return "A"
        if avg >= 75:
            return "B"
        if avg >= 60:
            return "C"
        return "F"
```

```test
check(s.average == 85.8 and s.grade == "B", "average updates when marks change", f"after adding 100: {s.average!r}")
check(Student("Riya", [95, 92]).grade == "A", "Riya gets an A")
check(Student("Dev", []).average == 0, "Empty marks give 0")
```

@lesson 13.5 | Dataclasses | 20
@goal Let Python write `__init__`, `__repr__` and `__eq__` for you with `@dataclass`.

Many classes mostly hold data. Writing `__init__`, `__repr__` and `__eq__` for each is repetitive. The `dataclasses` module writes them for you:

```py
from dataclasses import dataclass

@dataclass
class Book:
    title: str
    author: str
    pages: int = 0

b = Book("Wings of Fire", "A. P. J. Abdul Kalam", 180)
print(b)
print(b == Book("Wings of Fire", "A. P. J. Abdul Kalam", 180))
print(b.pages)
```

The lines `title: str` declare the fields with **type hints** (more on those in Unit 14). Fields with defaults come after fields without.

## Lists as defaults

Never write `tags: list = []`: every object would share one list. Use `field(default_factory=list)`, which builds a fresh list for each object:

```py
from dataclasses import dataclass, field

@dataclass
class Student:
    name: str
    marks: list = field(default_factory=list)

a = Student("Aman")
b = Student("Riya")
a.marks.append(90)
print(a, b)
```

## Sorting and freezing

`order=True` makes objects sortable, comparing fields in order. `frozen=True` makes them unchangeable, like tuples:

```py
from dataclasses import dataclass

@dataclass(order=True)
class Candidate:
    score: float
    name: str

ranked = sorted([Candidate(130.0, "Aman"), Candidate(142.5, "Riya"), Candidate(118.0, "Dev")], reverse=True)
for c in ranked:
    print(c.name, c.score)
```

Dataclasses can have methods too; they're normal classes with the boring parts written for you.

:::predict
```py
from dataclasses import dataclass

@dataclass
class P:
    x: int
    y: int = 0

print(P(1), P(1) == P(1, 0))
```
- P(1) True
+ P(x=1, y=0) True
- P(x=1, y=0) False
- <P object> True
= The dataclass writes a __repr__ showing every field, and an __eq__ that compares the fields, so P(1) equals P(1, 0).
:::

:::recall
Q: What does `@dataclass` write for you?
A: `__init__`, `__repr__` and `__eq__`, based on the fields you declare.
Q: How do you give a dataclass field an empty list as its default?
A: `field(default_factory=list)`, never `= []`.
Q: What does `@dataclass(order=True)` add?
A: Comparison methods, so objects can be sorted by their fields in order.
:::

@lesson 13.6 | Project: Library tracker | 45 | project
@goal Design two cooperating classes with clear rules and errors, the way real application code is organised.

Your study group shares books. You'll build a small library system with two classes:

**`Book`** (a dataclass): `title`, `author`, and `borrower` (default `None`, meaning available).

**`Library`**:

- `__init__()`: starts with an empty dictionary of books, keyed by title.
- `add(title, author)`: adds a book. Raises `ValueError` if that title already exists.
- `borrow(title, member)`: marks the book as borrowed by member. Raises `KeyError` if there's no such title, `ValueError` if it's already borrowed.
- `give_back(title)`: makes it available again. Raises `ValueError` if it wasn't borrowed.
- `available()`: a sorted list of the titles nobody has borrowed.
- `borrowed_by(member)`: a sorted list of the titles that member has.
- `__len__`: the number of books.

```py norun
lib = Library()
lib.add("Wings of Fire", "A. P. J. Abdul Kalam")
lib.add("Godan", "Munshi Premchand")
lib.borrow("Godan", "Riya")
print(lib.available())          # ['Wings of Fire']
print(lib.borrowed_by("Riya"))  # ['Godan']
print(len(lib))                 # 2
```

:::tip
Write `Book` first, then `Library.__init__` and `add`, and test them before moving on. The checker tests each method separately, including the error cases.
:::

:::recall
Q: Why raise exceptions from methods like borrow() instead of printing a message?
A: The caller decides how to react (show a message, retry, log it), and the object's rules can't be ignored silently.
Q: What does composition mean?
A: One object holding others as attributes, like a Library holding Book objects.

```starter

```

```solution
from dataclasses import dataclass

@dataclass
class Book:
    title: str
    author: str
    borrower: str = None


class Library:
    def __init__(self):
        self.books = {}

    def add(self, title, author):
        if title in self.books:
            raise ValueError(f"{title} is already in the library")
        self.books[title] = Book(title, author)

    def borrow(self, title, member):
        book = self.books[title]
        if book.borrower is not None:
            raise ValueError(f"{title} is already borrowed")
        book.borrower = member

    def give_back(self, title):
        book = self.books[title]
        if book.borrower is None:
            raise ValueError(f"{title} wasn't borrowed")
        book.borrower = None

    def available(self):
        return sorted(t for t, b in self.books.items() if b.borrower is None)

    def borrowed_by(self, member):
        return sorted(t for t, b in self.books.items() if b.borrower == member)

    def __len__(self):
        return len(self.books)
```

```test
need("Library")
lib = Library()
lib.add("Wings of Fire", "A. P. J. Abdul Kalam")
lib.add("Godan", "Munshi Premchand")
lib.add("Gitanjali", "Rabindranath Tagore")
check(len(lib) == 3, "len() counts the books", f"len gave {len(lib)}")
check(lib.available() == ["Gitanjali", "Godan", "Wings of Fire"], "Everything is available at first, sorted", f"got {lib.available()}")
lib.borrow("Godan", "Riya")
lib.borrow("Gitanjali", "Riya")
check(lib.available() == ["Wings of Fire"], "Borrowed books leave the available list", f"got {lib.available()}")
check(lib.borrowed_by("Riya") == ["Gitanjali", "Godan"], "borrowed_by lists Riya's books, sorted", f"got {lib.borrowed_by('Riya')}")
check(lib.borrowed_by("Dev") == [], "Dev has nothing")
try:
    lib.borrow("Godan", "Dev")
    check(False, "Borrowing a borrowed book raises ValueError", "No error was raised")
except ValueError:
    check(True, "Borrowing a borrowed book raises ValueError")
try:
    lib.borrow("Harry Potter", "Dev")
    check(False, "Borrowing a missing title raises KeyError", "No error was raised")
except KeyError:
    check(True, "Borrowing a missing title raises KeyError")
try:
    lib.add("Godan", "Someone")
    check(False, "Adding a duplicate title raises ValueError", "No error was raised")
except ValueError:
    check(True, "Adding a duplicate title raises ValueError")

check("Godan" in lib.available(), "give_back makes the book available again")

    lib.give_back("Wings of Fire")
    check(False, "Returning a book that wasn't borrowed raises ValueError", "No error was raised")
except ValueError:
    check(True, "Returning a book that wasn't borrowed raises ValueError")
```
