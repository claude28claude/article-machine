@lesson B.1 | Statistics with Python | 25
@goal Describe a set of numbers with the right statistics and spot a real trend.

Data work starts with describing numbers honestly. Python's `statistics` module covers the basics without installing anything.

```py
import statistics as st

scores = [127, 133, 141, 144, 151, 155, 154, 165, 169]
print("mean:", round(st.mean(scores), 2))
print("median:", st.median(scores))
print("stdev:", round(st.stdev(scores), 2))
print("quartiles:", st.quantiles(scores, n=4))
```

- **mean**: the average. Pulled around by extreme values.
- **median**: the middle value when sorted. Robust to outliers.
- **mode** (`st.mode`): the most common value.
- **standard deviation** (`stdev`): how spread out the values are. Small means consistent.
- **quartiles**: the values that cut the sorted data into four equal parts.

## Mean or median?

One bad day can drag a mean down. Watch:

```py
import statistics as st

usual = [140, 142, 145, 143, 141]
with_bad_day = usual + [60]
print(st.mean(usual), st.median(usual))
print(round(st.mean(with_bad_day), 1), st.median(with_bad_day))
```

The median barely moves. When a few extreme values exist (incomes, house prices, one disastrous mock), report the median, or both.

## Is it really improving?

Comparing just the first and last value is a classic mistake: both could be flukes. Compare the **average of the first half** with the **average of the second half**:

```py
import statistics as st

scores = [127, 133, 141, 144, 151, 155, 154, 165, 169]
half = len(scores) // 2
early = st.mean(scores[:half])
late = st.mean(scores[-half:])
print(round(early, 1), round(late, 1), "change:", round(late - early, 1))
```

:::predict
```py
import statistics as st
print(st.median([5, 1, 9, 3]))
```
- 3
- 5
+ 4.0
- 4.5
= Sorted, the values are 1, 3, 5, 9. With an even count, the median is the average of the two middle values: (3 + 5) / 2.
:::

:::recall
Q: When is the median a better summary than the mean?
A: When there are outliers or skewed values: the median ignores how extreme they are.
Q: What does a small standard deviation tell you?
A: The values are close together: results are consistent.
Q: How do you check a trend more reliably than first vs last value?
A: Compare the average of the first half of the data with the average of the second half.
:::

@exercise B.1b | Percentile rank
Write `percentile_rank(score, all_scores)`: the percentage of scores in `all_scores` that are **strictly below** `score`, rounded to 1 place. In a list of 10 scores, being above 9 of them is 90.0.

```starter
def percentile_rank(score, all_scores):
    pass
```

```solution
def percentile_rank(score, all_scores):
    below = sum(1 for s in all_scores if s < score)
    return round(below / len(all_scores) * 100, 1)
```


@exercise B.1c | Trend detector
Write `trend(scores)` that compares the mean of the first half with the mean of the second half (for an odd count, ignore the middle value). Return `"improving"` if the second half is more than 2 marks higher, `"declining"` if it's more than 2 lower, else `"steady"`.

```starter
import statistics as st

def trend(scores):
    pass
```

```solution
import statistics as st

def trend(scores):
    half = len(scores) // 2
    change = st.mean(scores[-half:]) - st.mean(scores[:half])
    if change > 2:
        return "improving"
    if change < -2:
        return "declining"
    return "steady"
```

```test
need("trend", "function")
expect("trend([127, 133, 141, 144, 151, 155, 154, 165, 169])", "improving")
expect("trend([150, 148, 140, 135])", "declining")
expect("trend([140, 142, 141, 141])", "steady")
expect("trend([100, 0, 103])", "improving")
```

:::hints
- `half = len(scores) // 2`; the first half is `scores[:half]`, the second is `scores[-half:]`.
- With an odd count, those two slices skip the middle value automatically.
:::

@lesson B.2 | NumPy essentials | 25
@goal Work with whole arrays of numbers at once using NumPy: arithmetic, statistics, masks and 2D tables.

**NumPy** is the foundation of nearly all data and AI work in Python. Its `array` holds numbers of one type, packed tightly, and does maths on **all of them at once**, written like maths on a single number:

```py
import numpy as np

minutes = np.array([60, 45, 30, 90, 120])
print(minutes / 60)
print(minutes.sum(), minutes.mean(), minutes.max())
print(minutes.shape, minutes.dtype)
```

No loop: `minutes / 60` divides every element. This is called **vectorisation**, and it runs at the speed of compiled C code, which matters when you have millions of values.

## Masks: selecting with conditions

A comparison gives an array of True/False, and that array can select elements:

```py
import numpy as np

scores = np.array([127, 133, 141, 144, 151, 155, 154, 165, 169])
good = scores >= 150
print(good)
print(scores[good])
print(good.sum(), "tests at 150 or more")
print(scores[scores < 140].mean())
```

`good.sum()` counts the Trues, because True counts as 1.

## 2D arrays: tables

Rows can be tests and columns subjects. `axis=0` works **down the columns** (one result per column); `axis=1` works **across each row**:

```py
import numpy as np

# reasoning, english, maths, gk for three mocks
marks = np.array([
    [38, 35, 24, 30],
    [40, 37, 27, 29],
    [41, 36, 31, 33],
])
print(marks.shape)
print(marks.sum(axis=1))    # total per test
print(marks.mean(axis=0))   # average per subject
print(marks[:, 2])          # the maths column
```

`marks[:, 2]` means "every row, column 2".

:::tip
`.tolist()` turns an array back into a normal Python list, and `np.round(arr, 1)` rounds every element.
:::

:::predict
```py
import numpy as np
a = np.array([1, 2, 3, 4])
print((a * 10)[a % 2 == 0])
```
- [10 30]
+ [20 40]
- [2 4]
- [False True False True]
= a * 10 is [10 20 30 40]; the mask picks positions where a is even (2 and 4), which hold 20 and 40.
:::

:::recall
Q: What does vectorisation mean in NumPy?
A: Doing an operation on a whole array at once, like `arr / 60`, without writing a loop.
Q: How do you select only the values above 150 from an array called scores?
A: With a boolean mask: `scores[scores > 150]`.
Q: In a 2D array, what do axis=0 and axis=1 do in `.mean(axis=...)`?
A: axis=0 gives one result per column (down the rows); axis=1 gives one result per row.
:::

@exercise B.2b | Good days
Write `good_days(scores, cutoff)` that returns a tuple `(count, average)`: how many scores are at least `cutoff`, and their average rounded to 2 places (`0` if none). Use a mask.

```starter
import numpy as np

def good_days(scores, cutoff):
    pass
```

```solution
import numpy as np

def good_days(scores, cutoff):
    arr = np.array(scores)
    picked = arr[arr >= cutoff]
    if picked.size == 0:
        return (0, 0)
    return (int(picked.size), round(float(picked.mean()), 2))
```

```test
need("good_days", "function")
expect("good_days([127, 133, 141, 144, 151, 155, 154, 165, 169], 150)", (5, 158.8))
expect("good_days([10, 20], 50)", (0, 0))
expect("good_days([150], 150)", (1, 150.0))
```

:::hints
- `arr[arr >= cutoff]` keeps only the good scores.
- `.size` counts them; convert with `int()` and `float()` so the results are plain Python numbers.
:::

```starter
    pass

    pass
```

```solution
import numpy as np

def subject_means(marks):
    return np.round(np.array(marks).mean(axis=0), 1).tolist()

def best_test(marks):
    return int(np.array(marks).sum(axis=1).argmax())
```

## Selecting and filtering

```py
import pandas as pd

df = pd.read_csv("mock_tests.csv")
print(df[["test", "maths"]].head(3))     # some columns
weak = df[df["maths"] < 30]               # rows matching a condition
print(weak[["test", "maths"]])

```

`df["maths"] < 30` is a True/False column; using it inside `df[...]` keeps only the True rows, just like a NumPy mask. Combine conditions with `&` (and) and `|` (or), with brackets around each part: `df[(df["maths"] < 30) & (df["gk"] > 30)]`.

## New columns and sorting

```py

best = df.sort_values("total", ascending=False)

```

## Grouping

`groupby` splits the rows into groups, calculates per group, and combines the results. Here, the average total per month:

```py
import pandas as pd

df = pd.read_csv("mock_tests.csv")
df["total"] = df[["reasoning", "english", "maths", "gk"]].sum(axis=1)
df["month"] = pd.to_datetime(df["date"]).dt.strftime("%Y-%m")
print(df.groupby("month")["total"].mean().round(2))
```

That's split-apply-combine, the most powerful idea in pandas.

| Task | pandas |
| --- | --- |
| load a CSV | `pd.read_csv("file.csv")` |
| first rows | `df.head()` |
| one column | `df["col"]` |
| filter rows | `df[df["col"] > 10]` |
| sort | `df.sort_values("col", ascending=False)` |
| new column | `df["new"] = df["a"] + df["b"]` |
| per-group stats | `df.groupby("key")["col"].mean()` |
| counts | `df["col"].value_counts()` |

:::recall
Q: How do you keep only the rows of df where maths is below 30?
A: `df[df["maths"] < 30]`.
Q: How do you add a total column from columns a and b?
A: `df["total"] = df["a"] + df["b"]`.
Q: What does `df.groupby("month")["total"].mean()` give?
A: The average total for each month: split by month, average each group, combine.
:::

@lesson B.5 | Machine learning basics | 30
@goal Understand what a model learns, fit your first one (a straight line), and measure how wrong its predictions are on data it hasn't seen.

**Machine learning** means a program learns a rule from examples instead of you writing the rule. You give it **features** (inputs, like hours studied) and **labels** (the right answers, like the score), and it finds a pattern it can apply to new inputs.

The simplest model of all is a straight line: `score = slope * hours + intercept`. "Learning" means choosing the slope and intercept that fit the examples best. NumPy can do it in one call:

```py
import numpy as np

hours = np.array([1, 2, 3, 4, 5, 6, 7, 8])
scores = np.array([95, 104, 112, 118, 129, 135, 144, 151])
slope, intercept = np.polyfit(hours, scores, 1)
print(f"score = {slope:.2f} x hours + {intercept:.2f}")
print("Prediction for 10 hours:", round(slope * 10 + intercept, 1))
```

`np.polyfit(x, y, 1)` finds the line (a degree-1 polynomial) that makes the squared errors smallest. That method, **least squares**, is also what's inside the linear regression of every ML library.

## How wrong is it?

A model is only as good as its errors on **new** data. The **mean absolute error** (MAE) is the average distance between prediction and truth, in the same units as the data:

```py
import numpy as np

actual = np.array([120, 135, 150])
predicted = np.array([118, 140, 149])
print("MAE:", np.mean(np.abs(actual - predicted)))
```

## Train and test

If you judge a model on the same examples it learned from, it can look perfect while being useless, like memorising answer keys. So you **split** the data: learn from the training part, measure on the test part it never saw.

```py
import numpy as np

hours = np.array([1, 2, 3, 4, 5, 6, 7, 8])
scores = np.array([95, 104, 112, 118, 129, 135, 144, 151])
train_x, test_x = hours[:6], hours[6:]
train_y, test_y = scores[:6], scores[6:]
slope, intercept = np.polyfit(train_x, train_y, 1)
pred = slope * test_x + intercept
print("predicted", np.round(pred, 1), "actual", test_y)
print("test MAE:", round(float(np.mean(np.abs(pred - test_y))), 2))
```

:::warn
A model that fits training data **too** closely (a wiggly curve through every point) usually predicts new data badly. That's **overfitting**, the central danger in machine learning. Simple models and honest test sets are the defence.
:::

:::real
On your laptop, the library **scikit-learn** (`pip install scikit-learn`) wraps all of this, with dozens of models behind one interface: `model.fit(X_train, y_train)`, `model.predict(X_test)`, plus `train_test_split` and error metrics. Everything here carries straight over; Google Colab also has it preinstalled.
:::

:::recall
Q: What are features and labels?
A: Features are the inputs a model uses; labels are the correct answers it learns to predict.
Q: Why split data into training and test sets?
A: To measure the model on data it hasn't seen; scoring it on training data hides overfitting.
Q: What is mean absolute error?
A: The average size of the prediction errors, in the data's own units.
:::

```solution
import numpy as np
```

```starter
def evaluate(hours, scores, n_train):
```

## Setup on your laptop

1. Create an API key in the Claude Console at [platform.claude.com](https://platform.claude.com/). API use is paid per token (roughly per word), separately from a Claude.ai subscription, so set a spending limit in the Console.
2. In your project's virtual environment: `pip install anthropic`.
3. Put the key in an **environment variable**, never in your code:

| System | Command (then open a new terminal) |
| --- | --- |
| Windows | `setx ANTHROPIC_API_KEY "your-key"` |
| Mac / Linux | add `export ANTHROPIC_API_KEY="your-key"` to `~/.zshrc` or `~/.bashrc` |

:::warn
An API key is like a password linked to your money. Never paste it into code, chats, screenshots or GitHub. If one leaks, delete it in the Console at once and make a new one.
:::

## Your first call

```py norun
import anthropic

client = anthropic.Anthropic()   # reads ANTHROPIC_API_KEY from the environment

response = client.beta.messages.create(
    model="claude-opus-5-5",
    max_tokens=16000,
    betas=["server-side-fallback-2026-07-01"],
    fallbacks="default",
    system="You are a patient tutor for SSC exam aspirants. Answer in under 120 words.",
    messages=[{"role": "user", "content": "Explain Article 21 in simple words."}],
)

if response.stop_reason == "refusal":
    print("Claude declined this one.")
else:
    for block in response.content:
        if block.type == "text":
            print(block.text)
```

- `model` picks which Claude model answers.
- `system` sets the assistant's role and rules for the whole conversation.
- `messages` is the conversation so far, as a list of `{"role", "content"}` dictionaries.
- The reply comes back as a list of **content blocks**; the words are in the blocks whose `type` is `"text"`.
- `fallbacks="default"` (with its `betas` entry) lets the API automatically retry on another model in the rare case the first declines a request, so your app keeps working.

## Conversations need memory you keep

The API remembers nothing between calls. To chat, keep the list of messages yourself and send all of it every time, adding Claude's answer after each reply:

```py norun
import anthropic

client = anthropic.Anthropic()
history = []

while True:
    question = input("You: ").strip()
    if question.lower() in ("quit", "exit"):
        break
    history.append({"role": "user", "content": question})
    response = client.beta.messages.create(
        model="claude-opus-5-5",
        max_tokens=16000,
        betas=["server-side-fallback-2026-07-01"],
        fallbacks="default",
        system="You are a patient tutor for SSC exam aspirants.",
        messages=history,
    )
    answer = "".join(b.text for b in response.content if b.type == "text")
    print("Claude:", answer)
    history.append({"role": "assistant", "content": answer})
```
